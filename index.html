SDK

Python

Install linkshieldai from PyPI. It needs Python 3.10 or newer and includes a sync client, an async client and a command line tool.

pip install linkshieldai

Scan a URL

from linkshieldai import LinkShieldAI

client = LinkShieldAI(api_key="YOUR_API_KEY")
result = client.scan("https://example.com", mode="standard")

print(result.verdict)       # SAFE, MALICIOUS or UNKNOWN
print(result.request_id)
print(result.reason_codes)

if result.is_malicious:
    print("Block or review this URL")

Leave out api_key and the client reads LINKSHIELDAI_API_KEY. See Authentication for how to set it.

Deep scan with model analysis

result = client.scan("https://example.com", mode="deep", ai=True)
print(result.verdict, result.risk_score, result.confidence)

Async client

import asyncio
from linkshieldai import AsyncLinkShieldAI

async def main():
    async with AsyncLinkShieldAI(api_key="YOUR_API_KEY") as client:
        result = await client.scan("https://example.com", mode="standard")
        print(result.verdict)

asyncio.run(main())

Other endpoints

nsfw = client.nsfw_check("https://example.com")
print(nsfw.is_nsfw)

print(chimera.result)

Install linkshieldai from npm. It needs Node.js 18 or newer, works with ES modules and CommonJS, and ships its own TypeScript types.

npm install linkshieldai

Scan a URL

import { LinkShieldAI } from "linkshieldai";

const client = new LinkShieldAI({ apiKey: "YOUR_API_KEY" });
const result = await client.scan("https://example.com", "standard");

console.log(result.verdict);     // SAFE, MALICIOUS or UNKNOWN

console.log(result.reasonCodes);

if (result.isMalicious) {
  console.log("Block or review this URL");
}

Run the SDK on your server. Never call LinkShieldAI from browser JavaScript, because that exposes your API key.

SDK

Rust

Add linkshieldai and Tokio to Cargo.toml. The client is async and returns typed result structs.

[dependencies]
linkshieldai = "0.3"
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }

Scan a URL

use linkshieldai::{LinkShieldAI, ScanMode, ScanOptions};

#[tokio::main]
async fn main() -> linkshieldai::Result<()> {
    let client = LinkShieldAI::new("YOUR_API_KEY")?;
    let result = client
        .scan("https://example.com", ScanMode::Standard, ScanOptions::default())
        .await?;

    println!("{}", result.verdict); // SAFE, MALICIOUS or UNKNOWN
    println!("{:?}", result.request_id);
    println!("{:?}", result.reason_codes);

    Ok(())
}

Pass an empty string to LinkShieldAI::new and the client reads LINKSHIELDAI_API_KEY.

Scan options

let options = ScanOptions { ai: true, ..ScanOptions::default() };
let result = client.scan("https://example.com", ScanMode::Deep, options).await?;

Other endpoints

use std::path::Path;

let nsfw = client.nsfw_check("https://example.com").await?;
println!("{}", nsfw.is_nsfw);

let chimera = client.chimera("https://google.com").await?;
println!("{:?}", chimera.result);

let image_bytes = client.get_screenshot("05046f.png", None).await?;
client.get_screenshot("05046f.png", Some(Path::new("site.png"))).await?;

API reference

Authentication

Send your API key in the Authorization header of every request.

Authorization: Bearer YOUR_API_KEY

Set the key for the SDKs and command line

The SDKs and the command line tool read LINKSHIELDAI_API_KEY when you don't pass a key.

# macOS and Linux
export LINKSHIELDAI_API_KEY="YOUR_API_KEY"

# Windows PowerShell
$env:LINKSHIELDAI_API_KEY = "YOUR_API_KEY"

Keep API keys on your server. Never put them in browser JavaScript or commit them to a public repository.

/nsfw/site and /chimera also accept the key as a key query parameter for older clients. Use the header in new code, since URLs often end up in logs.

API reference

Rate limits

Limits depend on your plan. The developer portal shows your per-minute, hourly and daily limits and your monthly allowance.

Responses from /v1/scan include these headers:

HeaderMeaning
X-RateLimit-LimitRequests allowed per minute.
X-RateLimit-RemainingRequests left in the current minute.
X-RateLimit-ResetLength of the rate limit window in seconds.
X-Monthly-Usage-UsedRequests counted this month.
X-Monthly-Usage-LimitYour monthly allowance. Sent when your plan has one.
X-Monthly-Usage-RemainingRequests left this month. Sent when your plan has a monthly allowance.
Retry-AfterSeconds to wait before trying again. Sent with HTTP 429.
X-Request-IDThe ID of this request. Include it when you contact support.

When you go over a limit the API returns HTTP 429. Wait for the number of seconds in Retry-After, then try again. The SDKs retry 429 responses for you.

Recommended

Scan a URL

POST
https://api.linkshieldai.com/v1/scan

Send a JSON body with the URL to check. You get back a verdict and the reasons behind it.

Request body

FieldTypeDescription
urlstringRequiredThe http or https URL to scan, up to 940 characters. Private and local addresses are rejected.
modestringstandard, detailed or deep. Defaults to standard.
aibooleanAdds model analysis in deep mode. Defaults to false.
include_signalsbooleanAdds a signals object to the response. Defaults to false.
 
curl -X POST https://api.linkshieldai.com/v1/scan \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com","mode":"standard"}'

Modes

ModeWhat it adds
standardFast reputation and threat feed check.
detailedAdds page preview, brand and screenshot signals when available.
deepAdds page fingerprinting when earlier signals are inconclusive.

Every mode follows the link's redirects and checks the page it ends on. That page is returned in url.final.

Detailed and deep scans load the page, so they take longer than standard scans.

Model analysis

Send "ai": true with deep mode to add model analysis when page fingerprinting is inconclusive. It is off by default and has no effect in other modes. confidence and risk_score are only filled in when the model runs.

{"url": "https://example.com", "mode": "deep", "ai": true}

Raw signals

Send "include_signals": true to see what each source returned before the verdict was decided. Use it if you want to apply your own rules. The verdict is the same either way.

"signals": {
  "url_reputation": "safe",
  "domain_reputation": "unknown",
  "threat_feed": "malicious",
  "external_reputation": false,
  "allowlist": {"fandom": false, "carrd": true},
  "degraded": false
}

url_reputation, domain_reputation and threat_feed are malicious, safe or unknown. degraded is true when a lookup failed, which means the verdict rests on fewer sources than usual. Signals describe url.final, the page the link ends on.

Example response

{
  "request_id": "7f4d...",
  "url": {
    "submitted": "https://example.com",
    "normalized": "https://example.com/",
    "redirects": [],
    "final": "https://example.com/",
    "redirect_chain": []
  },
  "mode": "standard",
  "verdict": "SAFE",
  "confidence": null,
  "risk_score": null,
  "threat_categories": [],
  "reason_codes": ["KNOWN_SAFE_MATCH"],
  "brand_target": null,
  "screenshot_url": null,
  "scanned_at": "2026-06-21T12:00:00.000Z",
  "freshness": "live",
  "engine_version": "linkshield-v1"
}

UNKNOWN is not SAFE. It means no decisive signal was found. Hold these links for review or treat them with caution.

Response fields

FieldTypeDescription
request_idstringUnique ID for this request. Also sent in the X-Request-ID header.
url.submittedstringThe URL you sent.
url.normalizedstringThe URL you sent, with a lowercase scheme and host and no fragment.
url.redirectsarrayURLs found inside the submitted URL's query string, such as a redirect parameter.
url.finalstringWhere the link ends up after its redirects. The verdict describes this page. The same as url.normalized when there is no redirect.
url.redirect_chainarrayEvery URL the link redirected through, in order, ending with url.final. Empty when there is no redirect.
modestringThe mode that was used.
verdictstringSAFE, MALICIOUS or UNKNOWN.
confidencenumber or nullSet only when model analysis ran.
risk_scorenumber or nullSet only when model analysis ran.
threat_categoriesarrayCategories that apply to the URL. Empty when none apply.
reason_codesarrayShort codes that explain the verdict, such as KNOWN_SAFE_MATCH.
brand_targetstring or nullThe brand the page appears to impersonate. From detailed and deep scans.
screenshot_urlstring or nullA screenshot of the page from a detailed or deep scan, when one was captured.
data_collection_successbooleanDetailed and deep scans only. true when the page was reached and page evidence was collected.
scanned_atstringWhen the scan ran, in UTC (ISO 8601).
freshnessstringlive
engine_versionstringThe version of the scanning engine.
signalsobjectOnly present when you send include_signals. See Raw signals above.

Download a screenshot

GET
https://api.linkshieldai.com/screenshot/{file_name}

Detailed and deep scans can return a screenshot_url. Open it directly, or pass the URL or its file name to an SDK to save the image.

curl -o site.png https://api.linkshieldai.com/screenshot/05046f.png \

The response is the image file. An unknown file name returns HTTP 404 with {"error": "File not found"}.

Endpoint

NSFW check

GET
https://api.linkshieldai.com/nsfw/site?url={url}

Checks whether a URL's domain is flagged as NSFW. URLs inside its query string, such as a redirect parameter, are checked too.

curl "https://api.linkshieldai.com/nsfw/site?url=https://example.com" \
  -H "Authorization: Bearer YOUR_API_KEY"

Response

{"result": "True"}

result is the string "True" or "False", not a boolean. The SDKs turn it into a boolean for you as is_nsfw or isNsfw.

Errors

Errors on this endpoint use an Error key with a capital E.

StatusResponseWhen
400{"Error": "URL parameter is missing."}No url in the query.
400{"Error": "key parameter is missing."}No API key was sent.
400{"Error": "Invalid URL format."}The URL is not a valid http or https URL.
400{"Error": "URL is too long. max char(940)"}The URL is longer than 940 characters.
429{"Error": "Key rate limit exceeded."}You reached a usage limit.
500{"Error": "An error occurred."}The check failed. Try again later.

Endpoint

Chimera

GET
https://api.linkshieldai.com/chimera?url={url}

Chimera combines reputation data, fingerprint matching and AI detection to classify a URL. The response contains only the final result and the URL that was scanned.

curl "https://api.linkshieldai.com/chimera?url=https://google.com" \
  -H "Authorization: Bearer YOUR_API_KEY"

Responses

{"result": "Might be malicious", "url": "https://somethingmalicious.com"}
{"result": "likely safe", "url": "https://google.com"}
{"result": "UNKNOWN", "url": "https://example.com"}
FieldTypeDescription
resultstringlikely safe, Might be malicious or UNKNOWN.
urlstringThe URL that was scanned. If you leave out the scheme, http:// is added.

UNKNOWN is not a guarantee that the URL is safe. It means Chimera did not find enough evidence, including when PhishPrint finds a suspicious but unconfirmed match.

Errors

StatusResponseWhen
400{"error": "Missing \"key\" or \"url\" parameter."}No url in the query, or no API key.
400{"error": "Invalid or unreachable URL."}The URL is not valid, can't be reached, or points to a private address.
400{"Error": "Invalid url format."}The URL is malformed. Note the capital E.
429{"error": "API key rate limit exceeded."}You reached a usage limit.
502{"error": "Unable to scan URL."}The page could not be fetched for analysis.

Error handling

The SDKs raise a specific error for each kind of failure. Every result object keeps the untouched API response in raw.

WhenPython and JavaScriptPHPRust
No API key was providedAuthenticationErrorAuthenticationExceptionLinkShieldAIError::Authentication
HTTP 429RateLimitErrorRateLimitExceptionLinkShieldAIError::RateLimit
Any other error statusAPIStatusErrorApiStatusExceptionLinkShieldAIError::Status
Bad JSON or an error payloadAPIResponseErrorApiResponseExceptionLinkShieldAIError::Response
Timeout, DNS or connection failureAPIConnectionErrorApiConnectionExceptionLinkShieldAIError::Connection
 
from linkshieldai import LinkShieldAI, RateLimitError

client = LinkShieldAI()

try:
    result = client.scan("https://example.com")
except RateLimitError as error:
    print("Slow down. Retry after", error.retry_after, "seconds")

Retries and timeouts

By default the SDKs wait up to 10 seconds per request and retry twice after a connection failure or an HTTP 429, 502, 503 or 504. You can change the timeout and retry count when you create the client.

Security

  • Always call the API over HTTPS.
  • Keep API keys on your server. Never put them in browser JavaScript or public repositories.
  • Rotate a key in the developer portal if you think it leaked.
  • Treat UNKNOWN as unverified. Don't auto-approve it.
  • Handle 429 responses in bots and high-volume pipelines so a burst of links doesn't stop your service.
  • No scanner catches every threat. Use LinkShieldAI alongside your own review process.
